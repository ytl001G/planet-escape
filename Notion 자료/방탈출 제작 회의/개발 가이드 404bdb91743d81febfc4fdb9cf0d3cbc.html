7-3. 메인 컴퓨터 연출

  • D: 부팅·로그인 시퀀스 애니메이션.
  • D: 기억 검색 오류 → 안전 모드 전환 연출(오류 로그 → 경고 → 계정 5개 잠김).
  • D: 안전 모드 현황판 카드 상태 전환 애니메이션, 현재 차례 강조.
  • C: ALONE 입력 화면 색 단서 배치·등장.
  • C: 화면 정지·글리치 → 주황 V 등장(CSS 또는 캔버스).
  • C: LOVE 인터랙션: 글자 타일 컴포넌트, 입력 차단 상태, 타일 소멸 애니메이션(외부에서 순차 지시 가능), V 등장, 드래그&드롭(터치·마우스), 슬롯 스냅, 완성 판정 콜백, VEA↔EVA 모핑.
  • C: 레버 활성화 안내 화면.
  • D: 탈출 엔딩: 시스템 로그가 하나씩 꺼지는 셧다운 → 암전.
  • D: 행성 엔딩: 좌표·생체 반응 스크롤, "여기는 알파" 반복 송출 화면.

7-4. 오펠리아 기록집 (A)

  • 페이지 넘김 UI(스와이프·버튼), 양방향, 넘김 애니메이션.
  • 페이지 모델: 앞쪽·뒤쪽 섹션, 구역별 잠금 페이지 삽입, 섹션 노출 여부는 props.
  • 강조 글자 렌더, 48일 침입 글꼴 페이지, 노아 숨겨진 기록 페이지 삽입 연출.
  • 낭독 하이라이트: 문단 id를 받으면 해당 문단으로 스크롤·강조.

7-5. 알렉스·노아·에바 (A)

  • 알렉스: 로그 말소→잠금 표시 전환 연출, 2부 로그 더보기.
  • 노아: 메모·노란 암시 레이아웃, 2차 암호칸 동시 표시.
  • 에바: 암전→점등, 비상 이륙 시스템 패널(계기 애니메이션), 마지막 기록 이름 치환(토큰 단위 글자 교체, 색 유지, 순차 재생), 메일 뷰.

7-6. 힌트폰 (이현민)

  • 앱 셸: 상태바, 탭 또는 화면 전환, 세로 레이아웃.
  • 1부 퀘스트 홈: 목표 카드, 우주선 지도 SVG 하이라이트, 안전 모드 감지 알림 애니메이션.
  • 2부 비아 챗: 메시지 리스트, 순차 등장, 타이핑 인디케이터, 아바타, 자동 스크롤.
  • 모드 전환 연출(릴리 프로그램 → 비아).
  • 힌트 입력(키패드/텍스트)과 힌트 렌더: 헤드리스 컴포넌트에 스타일 입히기, 단계 이동·정답·오류 상태.
  • 스토리 카드 템플릿(인물색·서명).
  • 보너스 패턴 락: 3×3 드로잉 UI. 판정은 서버로 보내고 화면은 그리기와 결과 표시만.
  • 성공 카드, 연결 상태 표시.

7-7. 콘텐츠·소재 제작 (전체)

  • 원고 교정 후 데이터 파일화, 마크업 적용 검수.
  • 우주선 지도 SVG(방별 하이라이트 레이어), 주황 V·VEA 로고, ALONE 타일 소재, 아이콘.
  • 글꼴 라이선스 확인, 손글씨·침입자 글꼴 확보.

7-8. 품질·실기 검증 (전체)

  • 실제 모니터 해상도·비율, 터치 입력, 한글 IME, 자동 포커스.
  • 저사양 기기 애니메이션 성능, 3~4시간 세션 메모리 누수.
  • 모든 state 조합 스냅샷 검수(디버그 패널 기준).
  • 오프라인·새로고침 후 같은 state로 복원되는지 확인(RoomKit 연동 전 단계에서는 로컬 mock으로).

대체로 쓸 만하지만, 그대로 가면 A가 과부하, B가 병목, C·D와 A 사이에 중복/의존이 생기는 세 군데가 걸립니다. 저장소 현황(master의 플레이스홀더 컴포넌트, feat/design-fx 예시)과 대조해 본 결과입니다.

1. A가 가장 무겁다

  • 오펠리아 기록집(양방향 넘김·페이지 모델·낭독 하이라이트)만으로도 LOVE 인터랙션과 맞먹는 단일 최대 작업입니다.
  • 여기에 알렉스·노아·에바까지 방 4개를 얹었습니다. 특히 에바는 암전→점등, 계기 애니메이션, 토큰 단위 이름 치환, 메일 뷰까지 네 가지가 따로 놉니다.
  • 게다가 A의 작업은 전부 B의 뷰어(일지·통신 로그·메모) 위에 올라가므로, B가 끝나기 전엔 A가 제대로 시작을 못 합니다.

2. B는 모두의 선행 작업이라 1주차 병목

  • 암호 입력·알림창·뷰어 3종·바탕화면은 A·C·D가 전부 기다리는 기반입니다.
  • 다행히 master에 props 계약과 쇼케이스가 이미 있어서, B가 "계약 먼저 고정 → 스타일 나중"으로 가면 나머지는 플레이스홀더 위에서 병렬 진행이 가능합니다. 이 순서를 명시해 두는 게 좋습니다.
  • 온스크린 키보드 + 한글 IME 여부가 미정인데, 들어가면 B 분량이 크게 늘어납니다. 터치 모니터 결정을 먼저 받으세요.
  • 현재 DocumentDialog.tsx 하나가 모든 문서 종류를 다 받고 있어서, B의 뷰어 3종과 A의 방 4개가 한 파일에 몰립니다. 뷰어별로 파일을 먼저 쪼개야 충돌이 안 납니다.

3. 중복·누락

  • 글리치: C(화면 정지·글리치→V)와 D(전환 효과 세트의 글리치)가 따로 만들게 됩니다. D가 만들고 C가 쓰는 걸로 정리.
  • 알렉스 말소→잠금 전환·[더보기]: B의 통신 로그 뷰어가 이미 말소·잠금·더보기를 렌더하므로 A의 알렉스 항목과 겹칩니다.
  • 이메일 뷰어: 6-2엔 4번째 레이아웃으로 있는데 7-2엔 빠져서 에바 메일 뷰가 A에게 떨어집니다.
  • 7-7·7-8 "전체": 지도 SVG(힌트폰·현황판), 주황 V(C·힌트폰), ALONE 타일(C)은 선행 소재인데 주인이 없습니다. 디버그 패널·스냅샷 검수도 한 명이 맡아야 합니다.

제안 조정

  • A 김주원) 오펠리아 + 노아.
  • B 정석현) 암호 입력, 알림창, 뷰어 4종(메일 추가), 알렉스 전환.
  • C 김호현) 바탕화면 + 레버 안내 + ALONE 색 단서 + 주황 V 등장 + LOVE. 메인 컴퓨터 화면 주인으로 일관됩니다.
  • D 이서준) 기존 연출 전부 + 에바(암전→점등은 이미 D의 유휴·암전 항목, 계기·이름 치환은 연출) + 글리치 공용화
  • 이현민: 힌트폰 그대로. phone/이 분리돼 있어 독립성이 가장 좋습니다. 지도 SVG는 이현민이 만들고 현황판(D)이 재사용.
  • 홍은기: 전체검수

이렇게 하면 A·B·C·D 분량이 "큰 것 하나 + 작은 것 몇 개" 수준으로 비슷해지고, 같은 파일을 두 사람이 만지는 곳이 줄어듭니다.
